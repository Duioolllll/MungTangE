# MungTangE 뭉탱이 2.0

**복잡한 스킬 실행기 대신, 프롬프트 하나로 디자인 → 개발 → 검증까지.**

**[SKILLS.md 핵심 프롬프트](SKILLS.md)** · [스킬 설치용 SKILL.md](skills/mungtange/SKILL.md) · [브랜드 디자인 디렉션](skills/mungtange/references/BRAND-DIRECTION.md) · [실전 심화 가이드](skills/mungtange/references/DEEP-INTEGRATION.md)

MungTangE는 웹디자인·프론트엔드·UX에 집중한 **프롬프트 중심 Agent Skill**입니다. AI가 작업을 이해하고 필요한 전문가 관점을 골라서 실제 구현과 검증을 한 흐름으로 수행하도록 설계했습니다.

> **필수 설치 없음. 필수 API 없음. 필수 CLI 없음. 추가 JSON 보고서 없음.**  
> 오직 [SKILLS.md](SKILLS.md)를 AI의 프로젝트 지침이나 대화에 전달하면 됩니다. 실제 파일 수정·브라우저 검사·코드 실행은 사용 중인 AI의 도구 권한에 따라 달라집니다.

## 이렇게 쓰세요

**1. [SKILLS.md](SKILLS.md)의 전체 내용을 열어 AI 에이전트의 지침으로 전달하세요.**

Codex, Claude Code, OpenCode, Copilot, Gemini, ChatGPT 등에서 프롬프트 지침으로 사용할 수 있습니다. 각 도구가 `SKILLS.md`를 자동 인식한다고 가정하지 마세요. 프로젝트 지침 파일에 내용을 붙여넣거나 읽을 파일로 명시하세요. 이 저장소의 [AGENTS.md](AGENTS.md)는 루트 SKILLS.md를 명시적으로 가리킵니다.

**2. 평범하게 작업을 요청하세요.**

~~~text
내 기존 Next.js 프로젝트를 분석해서 학교 커뮤니티 대시보드를
새롭게 디자인하고 실제 코드로 구현해줘.
모바일·키보드·로딩·에러 상태까지 검증하고 문제가 있으면 수정해줘.
~~~

**3. MungTangE가 프롬프트만으로 실행 절차를 결정합니다.**

~~~text
요청 분석
    ↓
전문가 관점 선택 (UX · 디자인 · 프론트엔드 · QA 등)
    ↓
BRIEF → EXPLORE → DESIGN → BUILD → VERIFY → DELIVER
    ↓
실패 시 원인 분석 → 수정 → 재검증
    ↓
실제 결과물 + 검증 증거 + 남은 문제
~~~

CLI·외부 모델 호출·서브에이전트가 없어도 지침 자체는 작동합니다. **실제 하위 에이전트가 있는 도구에서는 필요할 때만** 독립 작업으로 분리합니다. 도구가 없으면 제공 가능한 결과를 직접 만들고 실행하지 못한 검사는 명확히 표시합니다.

## 브랜드 특화 랜딩페이지 업그레이드

개발자 프레임워크·오픈소스 라이브러리·개발 운영 도구·B2B SaaS는 **구매/설치 의사결정에 필요한 증거가 다릅니다.** 새 [BRAND-DIRECTION.md](skills/mungtange/references/BRAND-DIRECTION.md)는 제품 유형별 히어로·실제 증거·CTA·안티패턴을 구분하고, PyNext(Python + Rust 실험적 프레임워크)의 **세 가지 경쟁 디자인(Design Direction Competition)**을 실제 근거·히어로·타이포·시그니처 모티프로 비교하고 최종 방향을 선정하는 예시를 제공합니다. **Brand Identity Engine**은 선택된 방향을 제품만의 일관된 시각 규칙으로 변환합니다.

실제 디자인 수정이 필요하면 [VISUAL-LOOP.md](skills/mungtange/references/VISUAL-LOOP.md)에 따라 **1440·768·390px 스크린샷 → Visual Critic Loop → 관찰된 문제 수정 → 동일 환경 재검증**를 수행합니다. 브라우저가 있는 환경에서는 [선택형 캡처 CLI](scripts/visual-capture.mjs)가 화면별 PNG와 측정 사실을 저장합니다. 시각 품질 점수는 자동으로 만들어내지 않으며, 브라우저가 없으면 검증 결과를 NOT RUN으로 기록합니다.

브라우저 설치 환경에서 테스트용 페이지로 **실제 캡처/비교 코드가 동작하는지** `npm run visual:smoke`로 검사할 수 있습니다. 이 테스트는 PyNext 랜딩의 품질 향상이나 MungTangE 점수 상승을 뜻하지 않습니다. 별도 Playwright 설치가 필요하며 일반 `npm run verify`에는 포함되지 않습니다.

## 포함된 기능

| 영역 | 프롬프트의 행동 지침 |
| --- | --- |
| Design | 제품에 맞는 스타일, 타이포·컬러·레이아웃·반응형 설계 |
| UX | 사용자 여정, 접근성, 입력·로딩·오류·완료 상태 |
| Frontend | 기존 프로젝트 분석, 작은 수직 기능 단위 구현, 회귀 방지 |
| Web QA | 키보드·반응형·스크린샷·성능·보안 검증 **(도구가 있을 때 실제 실행)** |
| Skills | 과제에 맞는 참조 방법 선택, 출처·라이선스·보안 확인 |
| Model Output | 증거 기반 완료 보고, 거짓 통과 방지, 실패 시 원인 분석 |
| Orchestration | 의존성·파일 소유권 관리, 필요할 경우에만 병렬 실행 |
| Delivery | 변경 파일·검증 내용·한계·승인 단계 정리 |

**300개 전부에 대한 실제 참조 경로:** 300개 각각의 SHA가 고정된 원본을 읽고, 항목별 활성화 단서·목차·원문 절차의 행 번호를 가진 [선택형 지식 라우터](skills/mungtange/references/knowledge/ROUTER.md)를 생성했습니다. 작업에 맞는 작은 묶음을 고른 뒤 필요한 원본만 확인합니다. **다만 이건 300개 전문가 심층 분석이 아니라 자동 구조 추출**입니다. 직접 해석한 실전 방법론은 [대표 10개 출처의 심화 가이드](skills/mungtange/references/DEEP-INTEGRATION.md)에 있고, [전체 출처 검증 기록](docs/SOURCE-AUDIT.md)은 별도 보관합니다.

## 300개 심층 해석까지 확장하기 (선택적 모델 실행)

300개 원본에 **모두 접근 가능한 것**과 300개의 실행 기법을 **모두 의미적으로 검토한 것**은 다릅니다. 후자를 위한 [증거 검증형 큐레이션 파이프라인](docs/CURATION.md)을 제공합니다. 외부 AI를 선택한 경우 원문 전체를 분석하고 실행 지침·적용 조건·원문 행 번호를 만들며, 검증 실패 결과는 사용하지 않습니다.

**외부 AI 모델 사용은 별도 승인과 실행 설정이 필요합니다.** 자동 생성 결과는 독립 검토 이전에 전문가 리뷰로 표시되지 않습니다.

## 추가 설치는 완전히 선택 사항

기존 Agent Skills 형식의 설치가 편하면 아래 명령어를 사용해도 됩니다.

~~~bash
npx skills add Duioolllll/MungTangE --skill mungtange
~~~

표준 설치기는 `skills/mungtange/SKILL.md`를 읽습니다. 이 파일은 루트 `SKILLS.md`에서 `npm run sync:skill`로 생성되며 **설치 경로에 맞게 링크가 변환**됩니다. 핵심 프롬프트는 단독으로 동작합니다. 필요할 때만 `references/DEEP-INTEGRATION.md` 또는 `references/knowledge/ROUTER.md`에서 특정 분야의 실제 원문 출처를 찾아 적용합니다. 300개를 매번 컨텍스트에 넣지 않습니다. 일반적인 작업에는 추가 로딩이 필요 없습니다. CLI는 필요 없습니다.

구형 `mungtange` Node CLI와 관련 실행 코드는 제거했습니다. 300개 카탈로그·지식 라우터·GitHub Pages는 출처 탐색 자료로 유지하며 기본 스킬 실행에는 필요하지 않습니다. 저장소의 브라우저 캡처 및 비교 스크립트는 **전체 저장소를 체크아웃했을 때만** 사용할 수 있습니다. 표준 스킬 설치는 `SKILL.md`와 `references/`를 제공하지만 루트 `scripts/`를 설치하지는 않습니다.

## 개인 브랜드와 모바일 가독성

**브랜드의 정체성이 단순한 스타일보다 우선합니다.** 새 디자인을 만들 때는 실존하는 작업 기록·글·프로젝트·사용자 제공 정보에서 고유 신호를 찾고, 본문 구성·히어로·타이포·모티프·프로젝트 증거에 연결합니다. 개발자 이름만 바꿔도 그대로 재사용할 수 있는 디자인이라면 정체성 설계는 미완료입니다. 근거가 없으면 프로필을 지어내지 않고 임시 디자인임을 밝힙니다.

브랜드 랜딩은 서로 다른 **3안의 구성·콘텐츠 흐름·타이포·증거**를 비교합니다. 시안 설명 3개는 실제 구현 3개와 다르므로 명확히 구분합니다. 1440·768·390px 시각 검증에서는 단순 가로 넘침 외에 **모바일 보조 텍스트의 읽기 편안함**과 글 간격을 직접 확인합니다. 자동 측정 결과만으로 사람의 가독성이나 미적 완성도를 보증하지 않습니다.

## 한계

프롬프트는 AI의 작업 절차를 강화하지만, 도구 권한을 새로 만들어주지는 않습니다. 브라우저가 없는 AI는 실제 화면을 검증할 수 없고, GitHub 쓰기 권한이 없으면 PR을 만들 수 없습니다. MungTangE는 **하지 않은 검사를 통과했다고 말하지 않도록** 설계되어 있습니다.

## 개발 및 기여

출처 카탈로그·선택형 검증 스크립트·GitHub Pages는 유지하며 구형 Node CLI는 제거했습니다. 프롬프트 수정은 루트 `SKILLS.md`만 편집한 뒤 `npm run sync:skill`로 설치용 사본을 생성합니다. `npm run verify`는 생성 결과·검증 도구·출처 기록을 확인합니다. `npm run brand:validate`는 브랜드 명세의 구조만 검사하고, 실제 디자인 결과 평가는 별도의 브라우저·사람 검토가 필요합니다. 원문 재검증은 별도 수동 작업이며, **자동으로 추출한 원문 구조/키워드를 완성된 심층 리뷰나 효과의 증거로 부풀리지 않습니다.** 외부 SKILL.md의 라이선스는 해당 프로젝트에 남아 있으며 MungTangE에 자동 귀속되지 않습니다.
