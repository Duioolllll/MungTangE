# Upstream corpus integrity record (research only)

> **What this proves:** On 2026-11-12, an automated job downloaded all 300 cataloged upstream Git blobs and recomputed their Git SHA-1 hashes. All 300 downloads matched the pinned SHAs; 0 failed. This establishes byte/version identity for that run, **not** expert reading, endorsement, effectiveness, safety, licensing or current upstream validity.

## Separate three levels of evidence

| Level | What actually happened | What it does **not** imply |
| --- | --- | --- |
| **300 Git blob checks** | Fetched full source bytes and verified SHA, identified file structure | That 300 skills were carefully understood or safely executed |
| **Exploratory lexical scan** | Used 29 broad keyword rules during an earlier experiment | That topic hit counts reliably discriminate applicability |
| **10 directly inspected examples** | Read selected upstream SKILL.md documents and adapted concrete procedures | That every upstream rule or linked auxiliary resource was audited |

The old keyword hit counts were often too broad to be useful (e.g., one web state pattern matched 198/300). **They are not used for selecting playbooks, measuring quality or telling agents how many defects to find.** The shallow autogenerated DESIGN-DNA, WEB-ENGINEERING, and AGENT-HARNESS guides were removed from the installed skill.

## Where useful guidance actually lives

The optional [DEEP-INTEGRATION.md](../skills/mungtange/references/DEEP-INTEGRATION.md) contains task-specific original instructions based on **10 directly examined sources**. [PLAYBOOKS.md](../skills/mungtange/references/PLAYBOOKS.md), [QUALITY.md](../skills/mungtange/references/QUALITY.md), and [SECURITY.md](../skills/mungtange/references/SECURITY.md) provide targeted guidance. The compact root [SKILLS.md](../SKILLS.md) never requires loading these files for every task.

The [300-row source record](../research/source-audit.json) is intentionally placed in research and **not included** in installed skill contents. It contains exact source repository, path, blob SHA, verification status, byte count and a short outline; no third-party SKILL.md text is redistributed.

## Reproducing the checksum check

In a Node 20+ environment with GitHub access, run:

~~~bash
npm run audit:sources
npm run check:source-audit
~~~

This queries pinned Git blobs. A GitHub token can help rate limits but does not need write permissions. The manual [source-audit workflow](../.github/workflows/source-audit.yml) writes an artifact; it does not silently commit generated data. A maintainer must inspect and explicitly update the archive if upstream references or statuses change.

**Scope:** technical provenance only. The live installed skill never needs the research archive.
